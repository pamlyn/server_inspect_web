## 一、系统概述

服务器巡检系统是一套基于 Flask 的 **服务器资源巡检 + 业务数据稽核** Web 应用，核心能力包括：

1. **服务器资源巡检**：CPU、内存、磁盘、磁盘 IO、交换分区、网络、进程、慢 SQL、数据库等指标的采集与阈值告警。
2. **业务数据稽核**：MES 报工明细与报表、吊挂数据之间的对账比对，自动发现「报表多余 / 明细多余 / 数量不一致」等差异。
3. **自定义稽核脚本**：支持单库 SQL 稽核与跨库对比，可配置变量、规则引擎，并接入定时 / 日常 / 实时三种触发方式。
4. **自动化与通知**：定时巡检、日常巡检、实时监测三种模式，异常通过钉钉机器人推送。
5. **日志留痕**：所有巡检结果可持久化到日志数据库，支持查询、详情查看与定期清理。
6. **PG 容器配置管理**：通过白名单安全管理 PostgreSQL 容器的日志相关参数。

### 架构简述

- 入口 `app.py`：Flask 应用工厂，注册 7 个 Blueprint，启动时加载配置文件并启动调度器。
- 配置两层：`config.py` 提供默认值，`config/config.json` 运行时覆盖；保存配置后调度器自动重启以生效。
- 时区：容器内统一 `TZ=Asia/Shanghai`。

| Blueprint | 前缀 | 职责 |
|---|---|---|
| auth | `/` | 登录 / 登出 / 验证码 |
| inspection | `/api` | 巡检、数据稽查、导出、清理慢 SQL |
| config_mgmt | `/api/config` | 读写配置、测库、reload |
| scheduler | `/api/scheduler` | 调度状态、立即执行、实时监测线程 |
| custom_scripts | `/api/custom_scripts` | 自定义稽核脚本 CRUD + 执行 |
| logs | `/api/logs` | 巡检日志查询 / 详情 / 清理 |
| pg_config | `/api/pg` | PostgreSQL 容器参数管理 |

## 三、功能说明

### 3.1 快速巡检与完整巡检

通过侧边栏可对服务器进行 **单项快速巡检** 或 **完整巡检**，结果实时展示在右侧内容区，按「信息 / 警告 / 紧急 / 正常」分级显示，支持展开折叠查看明细。

#### 快速巡检（单项）

点击侧边栏「快速巡检」分组下的任一按钮，仅执行该单项检查：

| 巡检项 | 说明 |
|---|---|
| 系统信息 | 主机名、操作系统、内核、运行时间、负载等基础信息 |
| CPU | CPU 使用率，超阈值产生警告 / 紧急 |
| 内存 | 内存使用率，超阈值产生警告 / 紧急 |
| 磁盘 | 各挂载点使用率与剩余空间，超阈值告警 |
| 网络 | 网卡流量、连接状态 |
| 进程 | 关键进程运行状态 |
| 交换分区 | Swap 使用率 |
| 磁盘IO | 磁盘读写速率与 I/O 等待 |
| 慢SQL | 从数据库采集慢查询（支持去重） |
| 数据库 | 数据库连接与基本状态检查 |

#### 完整巡检

点击「完整巡检」按钮，一次性执行 **完整巡检项配置** 中勾选的所有项目（含资源巡检与数据稽核项）。完整巡检的执行项可在「系统配置 → 完整巡检项配置」中自定义。

> 手动触发的巡检结果会同时记录到巡检日志（若已启用日志库），并按规则推送钉钉通知。

### 3.2 数据稽查

「数据稽查」页面提供针对业务数据库的即席查询与对账能力。

#### 稽查类型

| 类型 | 说明 |
|---|---|
| 自定义SQL | 在选定数据库上执行任意查询语句，结果以表格展示，可导出 CSV |
| 工人产量与报工明细稽查 | 对比 MES 明细缓存分表与工人产量报表（含颜色尺码维度） |
| 工人产量与报工明细数据稽核(sfd) | sfd 口径的明细与报表对账 |
| MES报工明细与吊挂报工明细稽查 | 对比 MES 报工与吊挂（dg_route_record）的数量与合计 |

#### 对账差异状态（check_status）

工人产量类稽核通过 FULL OUTER JOIN + 哨兵值做 null-safe 比对，输出四种状态：

| 状态 | 含义 |
|---|---|
| 一致 | 明细汇总与报表完全匹配 |
| 报表多余记录 | 报表中存在、明细中缺失 |
| 明细多余记录 | 明细中存在、报表中缺失 |
| 数量不一致 | 两边都有但数量不同 |

#### 操作步骤

1. 选择「稽查类型」。
2. 选择「日期范围」（稽查类型为对账时需要；自定义 SQL 时可选）。
3. 选择「数据库」（MES / 吊挂中间库）。
4. 输入 SQL（自定义 SQL 模式）。
5. 点击「执行SQL」查看结果，或「导出结果」下载 CSV。

> 数据稽查支持跨月查询：MES 明细按月分表（`produce_mes_reporting_work_cache_{年}_{月}`），系统自动枚举覆盖月份并 UNION ALL，**最近 N 天上限 28 天**（保证最多跨 2 张分表）。

### 3.3 自定义稽核

「自定义稽核」用于执行预先在「系统配置 → 自定义稽核脚本配置」中保存的脚本，适合反复运行的周期性对账场景。

#### 操作步骤

1. 在「选择稽核脚本」下拉中搜索并选择一个已保存脚本。
2. 查看脚本内容与替换参数后的 SQL 预览。
3. 在「脚本参数配置」中填写变量值（日期 / 数值 / 文本 / 周期等）。
4. 可选：在「规则配置」中临时添加判断规则。
5. 点击「执行稽核」查看结果，可「导出结果」。

#### 脚本能力概览（在系统配置中创建）

- **两种执行模式**：
  - 单库模式（single_db）：在单个数据库执行 SQL，按规则判定异常行。
  - 跨库对比模式（cross_db）：在源库与目标库分别执行 SQL，按维度列对齐逐行比对，找出不一致或仅单库存在的数据。
- **变量系统**：占位符 `#{变量名}`，支持 text / number / date / time / period 类型；日期变量支持动态解析（today / yesterday / last_n_days / last_n_to_yesterday / last_n_to_today），周期变量支持当前月 / 上个月 / 当前年 / 去年等。
- **规则引擎**：分异常组与正常组，满足任一异常规则即判异常，异常优先于正常。
- **触发接入**：每个脚本可勾选是否接入「定时巡检 / 日常巡检 / 实时监测」。

> 关键约定：页面执行、脚本测试、定时 / 日常 / 实时通知三条路径共用同一套变量解析逻辑，确保动态日期口径完全一致，避免漏报。

### 3.4 巡检日志

「巡检日志」页面查询历史巡检记录。**前提：已在系统配置中启用「日志保存数据库」并完成建表。**

#### 功能

- **筛选查询**：按巡检类型、触发来源、状态、操作人、目标、关键字、时间范围筛选。
- **分页浏览**：支持自定义每页条数。
- **详情查看**：点击单条日志查看解析后的友好内容（含各项 info / warning / critical 明细）。
- **日志清理**：按「早于指定日期」或「保留最近 N 天」策略批量删除。

#### 日志状态

| 状态 | 含义 |
|---|---|
| success | 巡检成功且无异常 |
| warning | 存在警告级问题 |
| critical | 存在紧急级问题 |
| error | 巡检执行本身失败 |

#### 触发来源

`manual`（手动）、`scheduled`（定时）、`daily`（日常）、`real_time`（实时）。

> 日志库未启用时，巡检仍正常运行，仅不做持久化，日志页面会提示「日志数据库未启用」。

### 3.5 PG 配置

「PG配置」页面用于安全管理宿主机上 PostgreSQL 容器的日志相关参数（1.4.1 新增）。

#### 工作方式

- 系统通过挂载的 docker.sock 在应用容器内执行 `docker exec <PG容器> psql ...`，无需额外数据库凭据。
- **安全限制**：仅允许修改白名单内的参数，且取值经白名单校验，杜绝 SQL 注入；不支持任意 SQL 交互。

#### 可管理参数（白名单）

| 参数 | 含义 | 取值示例 |
|---|---|---|
| `log_statement` | 普通 SQL 执行日志 | none / ddl / mod / all |
| `log_min_duration_statement` | 慢查询阈值（ms） | 0=全记录，-1=关闭，>0=超时记录 |
| `logging_collector` | 日志收集器（postmaster 级，需重启 PG） | on / off |
| `log_rotation_size` | 单条日志文件最大 | 512MB / 1GB / 0 |
| `log_rotation_age` | 按时间轮转 | 1d / 60min / 0 |
| `log_directory` | 日志目录 | log |
| `log_filename` | 日志文件名 | postgresql-%Y-%m-%d.log |
| `log_truncate_on_rotation` | 轮转时截断 | on / off |
| `log_connections` | 记录连接 | on / off |
| `log_disconnections` | 记录断开 | on / off |

#### 操作

1. 选择目标 PG 容器与用户（默认 `mes_postgresql` / `postgres`，可保存）。
2. 查看各参数当前值、来源、上下文级别。
3. 修改单个参数：输入新值 → 保存（自动执行 `ALTER SYSTEM SET` + 可选 `pg_reload_conf`）。
4. **一键应用推荐配置**：快速设置「关闭普通 SQL 日志 / 慢查询阈值 10s / 关闭日志收集器 / 单日志 512MB」。

> ⚠️ `logging_collector` 为 postmaster 级参数，`pg_reload_conf` 不会使其生效，需重启 PG 容器。

### 3.6 清理慢 SQL 日志

点击侧边栏底部「清理慢SQL日志」按钮，系统会：

1. 自动发现宿主机上疑似数据库容器（PostgreSQL / MySQL / Mariaadb）。
2. 对每个容器的 Docker 日志文件执行 `truncate -s 0`（先尝试 sudo，失败回退普通权限）。
3. 返回每个容器的清理结果与清理后日志大小。

> 用途：当数据库容器运行日久、Docker JSON 日志文件膨胀占满磁盘时，一键清空历史日志释放空间。

## 四、巡检模式与通知机制

### 4.1 三种自动巡检模式

系统提供三种自动化巡检模式，可同时启用，互不冲突：

| 模式 | 触发方式 | 执行项来源 | 典型用途 |
|---|---|---|---|
| **定时巡检** | Cron 表达式（每 N 分钟 / 定点 / 自定义） | 定时巡检项 | 高频资源监控 |
| **日常巡检** | 每日固定时点（时:分） | 日常巡检项 | 每日业务对账汇总 |
| **实时监测** | 后台持续循环（每 N 秒） | 实时监测项 | 关键指标实时告警 |

三种模式均会：执行勾选巡检项 + 执行接入的自定义脚本 → 记录日志 → 按通知策略推送钉钉。

#### 实时监测的去重机制

为避免高频打扰，实时监测采用「**内容指纹去重**」：

- 异常内容（各异常项的 warnings/criticals）完全一致时，在冷却期内不重复通知；
- 异常内容发生变化时，立即通知；
- 冷却期过后，相同内容会再通知一次（起到周期提醒作用）；
- 异常消除后重置指纹，便于下次异常再次通知。

> 系统保证同一时刻只有一个监测线程运行（保存配置会先停止旧线程再启动新线程），避免重复通知。

### 4.2 钉钉通知机制

#### 通知分类

每类巡检项在通知中使用中文名称：系统信息、CPU使用率、内存使用情况、交换分区使用情况、磁盘使用情况、磁盘IO情况、进程状态、慢SQL检查、数据库检查、网络状态、工人产量与报工明细稽核（含/不含颜色尺码）、工人产量与报工明细数据稽核(sfd)、MES报工明细与吊挂报工明细稽核；自定义脚本使用脚本本身的名字。

#### 展示规则

- **数据稽核类**（工人产量 / MES吊挂）：**始终展示明细**，即使正常也显示「🟢 正常」段落。
- **其他类**：仅在异常时展示；正常时仅在汇总中体现。
- 慢 SQL 类在开启「显示异常详情」时附带慢查询明细。

#### 通知触发条件

| 模式 | 通知条件 |
|---|---|
| 定时巡检 | 发现异常（warning/critical）时通知，300 秒冷却 |
| 日常巡检 | 「仅异常通知」开启时仅异常通知；关闭时无论是否异常都通知 |
| 实时监测 | 按「内容指纹 + 冷却期」策略（见上） |
| 手动巡检 | 完整巡检按 scheduled 通知口径；单项按 user 通知口径 |

| 场景 | 操作 |

### 5.4 配置变更与生效

- **页面配置**：在「系统配置」修改并保存 → 调度器自动重启即时生效。
- **挂载文件直接编辑**：若直接编辑宿主机 `config/config.json`，需执行 `./deploy.sh restart` 让容器内进程重读配置。
- **前端 JS 改动**（仅开发场景）：需手动 bump `templates/base.html` 中的 `?v=` 缓存戳，否则浏览器使用旧缓存。

### 5.5 升级与重新部署

当有新版本镜像时：

```bash
./deploy.sh redeploy   # 拉取最新镜像 + 删除旧容器 + 用新镜像重建
```

`redeploy` 不会跑 `init`，因此 **保留现有挂载的配置文件**（config.json / custom_scripts.json），仅更新镜像并重建容器，配置与自定义脚本不丢失。

### 6.3 常见问题

**Q：登录密码忘了？**
A：出厂凭据硬编码为 `admin / Jack_59496`，如曾修改源码请参考 `modules/auth/helpers.py`。

**Q：日志页面提示「日志数据库未启用」？**
A：巡检功能不依赖日志库，但日志持久化需在「系统配置 → 日志保存数据库配置」中启用并「测试连接并创建表」。

**Q：保存配置后没生效？**
A：页面保存会自动重启调度器；若直接改了挂载的 config.json 文件，需 `./deploy.sh restart`。

**Q：数据稽查跨月查询报错？**
A：「最近 N 天」上限 28 天；「自定义日期范围」的开始与结束必须在同一个月。

**Q：实时监测通知太频繁 / 不通知？**
A：调整「相同异常内容抑制」秒数（冷却期）；确认「是否异常通知」与钉钉总开关已开启；注意内容相同会在冷却到期后再通知一次。

**Q：PG 配置改了 logging_collector 没生效？**
A：`logging_collector` 是 postmaster 级参数，`pg_reload_conf` 无效，需重启 PG 容器本身（非本应用容器）。

**Q：自定义脚本在定时任务里日期不对？**
A：所有路径共用 `get_variable_value()` 解析动态日期；请确认变量的 `date_range_type` 已正确设置，而非依赖保存时的快照。
